## 0. 速览（TL;DR）

| 项 | 结论 |
|---|---|
| 桌面端无法拖拽的根因 | Electron 主窗口宽 460px（< 768px 断点）→ `isMobileView()` 误判为手机 → 卡片 `draggable=false`，HTML5 拖拽整体被禁用，只剩"鼠标长按 600ms"的触摸路径，形同不可用 |
| 移动端无法拖拽的根因 | 长按激活后手指一移动，浏览器即把触摸接管为页面滚动并发出 `pointercancel`，拖拽被瞬间掐断（`touch-action: auto` 且未阻止 `touchmove` 默认行为） |
| 桌面端修复 | 新增 `isTouchMode()`（主指针为粗指针才算触摸），460px 窄窗口恢复 HTML5 拖拽 |
| 移动端修复 | 长按激活后挂非被动 `touchmove` + `preventDefault` 锁定滚动；拖拽引擎重写为 rAF + ref 直写 DOM |
| 回归结果 | 460px 桌面拖拽 ✅ / 1280px 桌面拖拽 ✅ / 移动端重排序 ✅（0 次 pointercancel）/ 移动端拖入子任务 ✅ |

## 1. 根因分析（真实浏览器事件级复现）

用 Vite dev + Playwright/Chromium 拦截后端 API 打桩，在两种设备形态下录制真实事件序列：

### 1.1 桌面端（Electron 主窗口 460×840）

- `electron/main.ts` 主窗口 `width: 460, minWidth: 360`；
- `platform.ts` 的 `isMobileView()` 以 `max-width: 768px` 媒体查询判定 → 窗口常态即"手机视图"；
- `TaskCard` 的 `draggable={!mobile}` → **draggable=false，HTML5 拖拽彻底关闭**；
- 桌面用户实际得到的是触摸版"按住鼠标 600ms 进入拖拽"路径——无提示、反直觉，等于不可用。

### 1.2 移动端（Android / 触摸设备）

录制到的事件序列（修复前）：

```
pointerdown@196,180/touch   ← 长按 600ms 后 ghost 出现（激活成功）
pointermove@196,212/touch   ← 手指开始移动
touchmove
pointercancel@0,0/touch     ← 浏览器判定为"滚动意图"，取消指针 → 拖拽当场死亡
touchmove × N               ← 后续移动全部失联
touchend                    ← 无任何 PUT 请求，排序不变
```

三个叠加问题：

| # | 问题 | 影响 |
|---|---|---|
| ① | 卡片 `touch-action: auto` 且拖拽期间未 `preventDefault(touchmove)` | 浏览器把触摸接管为滚动 → `pointercancel` → **拖拽必死**（无法拖拽的直接根因） |
| ② | 每次 `pointermove` 都 `setState` 更新 ghost 坐标 | 全列表每帧重渲染 → **卡顿** |
| ③ | "变子任务"落点区占卡片高度 40%（30%~70%） | 想插上/下方经常误落入中区 → **误触变子任务**；跨父级/优先级时桌面端无反馈、移动端强降级，两端行为不一致 |

## 2. 实现方案

### 2.1 交互模式判定：布局归布局，交互归交互（`src/lib/platform.ts`）

```ts
/** 主输入设备是否为粗指针（触摸屏，无鼠标悬停） */
const coarseQuery = window.matchMedia?.('(pointer: coarse)');

/** 触摸交互模式（原生移动端 + 触摸屏设备）：拖拽走长按路径；否则走 HTML5 拖拽 */
export function isTouchMode(): boolean {
  if (isNativeMobile) return true;
  return coarseQuery?.matches ?? false;
}
```

| 判定 | 用途 |
|---|---|
| `isMobileView()`（视口 ≤768px 或原生移动） | 纯**布局**行为：跑马灯开关、应用内提醒弹窗等，保持不变 |
| `isTouchMode()`（主指针 coarse 或原生移动） | **拖拽交互模式**：触摸设备=长按拖拽；鼠标设备（含 460px 窄窗口桌面）=HTML5 拖拽 |

> 关键收益：桌面 Electron 460px 窗口布局仍是手机样式，但拖拽恢复为标准 HTML5 鼠标拖拽。

### 2.2 桌面端：HTML5 拖拽（`TaskCard` + `TaskOutline` 现有链路修复）

- `draggable={!touchMode}`，`onDragStart` 写入 `task/id` + `effectAllowed='move'`；
- `dragover` 落点判定收敛为统一分区（见 2.4），**跨父级/跨优先级不再静默 return，统一降级为 child**（与移动端一致）；
- 修复**指示器残留**：hover 到自身/后代/无效目标时立即 `clearIndicator()`，不再残留上一目标的指示线；
- 卡片加 `user-select: none`，杜绝拖动时选中文本。

### 2.3 移动端：长按拖拽引擎重写（`TaskOutline.tsx`）

状态只存 `mobileDragId`（开始/结束各渲染一次），指针坐标、ghost 位置、指示器更新全部收敛到**单个 rAF 循环直写 DOM**：

```
长按 600ms（位移 <14px 容差）
   │
   ├─ navigator.vibrate(25)          震动确认进入拖拽模式
   ├─ body.classList.add('drag-active')
   ├─ 挂载全局监听：
   │    pointermove（passive）        → 只写 pointerRef
   │    pointerup / pointercancel     → 统一走 endMobileDrag（幂等）
   │    touchmove（non-passive）      → e.preventDefault() ★核心：阻止浏览器
   │                                     接管为滚动，从源头消灭 pointercancel
   │    contextmenu                   → preventDefault，压制长按系统菜单
   └─ 启动 rAF 循环（每帧一次）：
        ├─ ghost.style.left/top      幽灵卡片跟手（不经 React 渲染）
        ├─ autoScroll(pt)            距上/下边缘 96px 内自动滚动列表
        └─ updateDropAtPointer(pt)   findDropAtY → 约束校验 → moveIndicator + hint
   │
松开 → endMobileDrag(false) → 按最后落点 onReorder → 串行 PUT 排序
取消 → endMobileDrag(true)  → 清理全部状态，不产生任何请求
```

工程细节：

- **幂等结束**：卡片 `pointerup` 与全局 `pointerup` 双入口都会触发结束，`dragEndedRef` 保证只生效一次；
- **点击抑制**：拖拽结束后浏览器补发的 `click` 被 `suppressNextClick` 吞掉，避免误触发展开/收起；
- **滚动锁定**：`touchmove` 的 `preventDefault` 只在拖拽激活期间生效（进入/退出时挂/摘监听），不影响平时列表滚动——`touch-action` 无法中途修改（手势开始时即锁定），非被动监听是标准解法（dnd-kit 同款）；
- **渲染成本**：修复前每次 `pointermove`（60~120Hz）全列表 setState 重渲染；修复后整段拖拽只有 2 次渲染（开始/结束）。

### 2.4 落点分区统一（两端一致）

```
┌─────────────┐
│   上 40%    │ → before：插到目标上方（指示线在卡片上沿）
├─────────────┤
│   中 20%    │ → child：拖入为目标的子任务（虚线描边 + 绿色高亮 + 提示条）
├─────────────┤
│   下 40%    │ → after：插到目标下方（指示线在卡片下沿）
└─────────────┘
```

- 中区从 40% 收窄到 20%：重排（高频操作）更容易命中，变子任务（结构性操作）需要刻意瞄准；
- **约束规则**：`before/after` 仅对"同父级 + 同优先级"有效（排序先按优先级分组，跨组插入会被分组弹回）；跨父级/跨优先级时**两端统一降级为 child**，行为可预期；
- 拖到自己后代 / 列表空白无效区：清指示器，无操作。

### 2.5 样式优化（`src/index.css`）

| 项 | 说明 |
|---|---|
| `.drop-hint` | 落点提示条（深色圆角胶囊，`z-index:12`）：跟随指示线/目标卡片，文案明确结果——"松开：移到上方 / 移到下方 / 设为子任务"（绿色变体）。触摸拖拽常显（手指遮挡 + 精度低），桌面鼠标仅 child 区显示（指针已精确，指示线足够） |
| `.task-drag-ghost` | 从 768px 媒体查询提升为**全局**样式；`translate(-50%, -78%)` 抬高于手指上方，不遮挡落点；`touch-action:none`；宽度 `min(320px, 78vw)` |
| `.task-card` | `user-select:none` + `-webkit-touch-callout:none`，拖动/长按不再选中文本或弹系统菜单 |
| `body.drag-active` | 拖拽进行中全局禁选区、`cursor:grabbing`、列表 `overscroll-behavior: contain` |
| 落点指示器 | 保留原虚线 + 双端点样式；移动端加粗为 3px 实线（原有） |
| 长按预反馈 | `.long-press-ready`（缩放 1.02 + 描边高亮）提示"即将进入拖拽"，加 `vibrate(25)` 震动确认 |

### 2.6 两端交互流程对比

| 阶段 | 桌面端（鼠标） | 移动端（触摸） |
|---|---|---|
| 发起 | 按住卡片任意处直接拖动（`cursor: grab`） | 按住卡片 600ms（位移 <14px），震动 + 卡片微缩放确认 |
| 拖动中 | 源卡片半透明 (opacity .45)；指示线/child 高亮实时跟指针 | 幽灵卡片悬浮手指上方；指示线 + 提示条实时跟手指；近屏幕边缘自动滚动 |
| 精准落点 | 指针位置 = 落点，指示线即时反馈 | 20% 宽 child 区 + 提示条文案兜底，杜绝误判 |
| 结束 | 松开即重排，串行 PUT `sortOrder` | 同左；点按误触已被抑制 |
| 取消 | 拖出列表 / Esc（dragend 清理） | 移动中来电等系统打断（pointercancel）→ 静默清理，不发请求 |
