|---|---|---|

### 2.2 三个 React 根入口

`src/main.tsx` 按 `location.hash` 分发**三个独立的 React 根**，这是理解本项目前端结构的关键：

| Hash | 渲染内容 | 用途 |
|---|---|---|
| `#widget` | `<WidgetApp />` | 桌面小组件窗口（Electron 专属小窗） |
| `#reminder*` | `<ReminderPopup />` | 桌面提醒弹窗（Electron 弹出） |
| 其他 | `<App />`（包在 `ErrorBoundary` + `StrictMode` 内） | 主应用 |

### 3.3 通信模型（重要）

**只有客户端主动拉取，服务器从不主动推送。**

- 所有数据通过 `fetch` 走标准 HTTPS REST
- 鉴权：每次请求带 `Authorization: Bearer <token>`，token 存 `localStorage` 的 `dd_token`
- 触发时机：打开页面 / 切换视图 / 登录后拉一次；任何增删改后自动 `refresh()`
- **没有** WebSocket、SSE、轮询（除小组件 15 秒刷新）、推送通知（FCM / 个推）

那些看起来"自动"的行为，实际都是**本地**行为：

| 行为 | 位置 | 真相 |
|---|---|---|
| 小组件自动刷新 | `widget.tsx` | `setInterval(load, 15000)` 本地轮询 |
| 移动端提醒弹窗 | `App.tsx`（约 315 行） | `setInterval(check, 5000)` **纯本地**查任务 `reminderAt` |
| AI 周报自动生成 | `App.tsx`（约 342 行） | `setInterval(..., 30000)` 本地定时，到点调本地 AI 逻辑 |
| 小组件 ↔ 主窗口同步 | `electron/main.ts` | Electron 进程内 IPC 广播，**非服务器推送** |

### 5.2 安装步骤

```bash
# 1. 克隆仓库
git clone https://github.com/yan2468/Hpro_todo.git
cd Hpro_todo

# 2. 安装依赖（前后端共用一份 package.json）
npm install

# 3. 创建环境变量文件
cp .env.example .env
# 然后用编辑器填写实际值（见下方）
```

### 5.3 环境变量（`.env`）

`.env` 位于**项目根目录**，前后端共用一份：

| 变量 | 作用 | 示例 |
|---|---|---|
| `VITE_API_BASE` | **前端**：后端 API 地址（Vite 会注入 `import.meta.env`） | `http://localhost:8787` |
| `DATABASE_URL` | **后端**：PostgreSQL 连接串 | `postgres://user:pass@host:5432/dbname` |
| `JWT_SECRET` | **后端**：JWT 签名密钥（**务必改**成长随机串） | `change-this-to-a-long-random-secret` |
| `PORT` | **后端**：监听端口 | `8787` |
| `CORS_ORIGINS` | **后端**：跨域白名单，**JSON 数组格式** | `["http://localhost:5173","http://localhost"]` |

> ⚠️ **`CORS_ORIGINS` 必须是 JSON 数组**，因为 `server/index.ts` 用的是 `JSON.parse(rawCors)`：
> ```ts
> const corsOrigins = rawCors ? (JSON.parse(rawCors) as string[]) : true;
> ```
> ❌ 错误：`CORS_ORIGINS=https://a.com,https://b.com`（会 JSON.parse 抛错）
> ✅ 正确：`CORS_ORIGINS=["https://a.com","https://b.com"]`
>
> 不填则 `corsOrigins = true`，即允许所有来源（开发环境可用，生产不推荐）。

### 5.4 数据库初始化

```bash
# 方式一：脚本创建
node scripts/setup-db.cjs

# 方式二：手动执行 DDL
psql "$DATABASE_URL" -f server/schema.sql
```

后续如果表结构有增量变更（如加列），执行：

```bash
node server/migrate.cjs
```

> 线上 ECS 上，每次部署后端后都要在 `/var/www/dev-todo/` 下跑 `node migrate.cjs && pm2 restart dave-tasks-server`，否则会出现"接口 500 / 字段不存在"。

### 6.2 构建命令

| 命令 | 作用 | 产物 |
|---|---|---|
| `npm run build` | 只构建前端 | `dist/` |
| `npm run build:electron` | **PC 完整打包**（含 tsc + .cjs 复制 + electron-builder） | `release-out/` |

### 6.3 一键构建（`build.bat`）

**结构**：`build.bat`（3 行 ASCII 薄壳）→ `build.ps1`（真正逻辑）

`build.ps1` 的 4 个阶段：

```
[0/3] 清理 release-out（~260MB 中间产物）
        └─ 防 electron-builder 增量复用旧 dist 打进包
[1/3] PC 打包    npm run build:electron
[2/3] Android    npm run cap:sync → gradlew assembleDebug
[3/3] 打包归集   scripts/build_release.py
[DONE] 输出 release/ 内容清单
```

**最终产物（`release/`）**：

| 文件 | 大小 | 说明 |
|---|---|---|
| `🐮🐴的打工日志-电脑版.exe` | ~69 MB | **portable 单文件，双击即用，免解压** |
| `🐮🐴的打工日志-电脑版.zip` | ~107 MB | 完整目录备份（`win-unpacked/`） |
| `🐮🐴的打工日志-安卓版.apk` | ~6.1 MB | Android 安装包 |
| `dave-tasks-server.zip` | ~22 KB | 后端部署包 |

> 用户交付时：**PC 用 exe（双击即用），Android 用 apk（覆盖安装保留数据）**。zip 只是备份，不必给用户。

## 7. 关键模块与业务逻辑

### 7.1 状态管理：Context + Hooks（无 Redux）


### 7.2 接口层（`src/lib/api.ts`）

**`apiFetch(path, opts)`** 是唯一的请求出口，统一处理：

1. 自动加 `Content-Type: application/json`
2. 自动加 `Authorization: Bearer <token>`（从 `localStorage.dd_token` 读）
3. `fetch` 失败 → 抛中文错误「无法连接服务器 (${base})，请检查网络或点击「配置服务器」…」
4. `!res.ok` → 抛后端返回的 `body.error` 或 `请求失败 (${status})`
5. 成功 → `res.json()`

**Base 地址优先级**（`resolveBase()`）：

```
localStorage 'dd_api_base'   ← 用户在设置里手动填的（最高优先级）
        ↓（为空时）
import.meta.env.VITE_API_BASE  ← .env 里配的
        ↓（为空时）
DEFAULT_API_BASE              ← src/lib/platform.ts 里的硬编码默认值
```

**`EXPIRED_BASES` 软迁移机制**（重要）：

```ts
const EXPIRED_BASES = new Set<string>(['http://8.163.32.86:8787']);
```

老版本硬编码地址被列在这里，一旦在用户的 `localStorage` 里命中就**自动清除**，让其回落到默认值。这是为了老用户升级后不会继续请求已废弃的地址。
**迁移新域名时，务必把旧域名加进这个 Set**，否则老用户仍会请求旧地址且浑然不知。

> ⚠️ 注意：用户**主动**在设置里设回这些值不会被误清——清的是 localStorage 残留。

### 7.3 平台适配（`src/lib/platform.ts`）

| 导出 | 判定逻辑 | 用途 |
|---|---|---|
| `isElectron` | `!!window.electronAPI` | 是否 Electron 桌面端 |
| `isNativeMobile` | `Capacitor.isNativePlatform()` | 是否原生 App |
| `isMobileView()` | 原生 ‖ 视口 ≤ 768px | 是否走手机布局 |
| `isTouchMode()` | 原生 ‖ `pointer: coarse` | **决定拖拽路径**：触摸=长按拖拽，否则=HTML5 拖拽 |
| `DEFAULT_API_BASE` | 硬编码默认后端地址 | 见 [第 10 节](#10-当前进行中的工作) |

> ⚠️ **拖拽路径的坑**：桌面 Electron 窗口即使宽度 < 768px（手机样式布局），主指针仍是鼠标，**必须走 HTML5 拖拽**。若误用 `isMobileView()` 判断，会导致桌面端卡片 `draggable=false`，完全无法拖拽重排。所以拖拽判定用的是 `isTouchMode()` 而非 `isMobileView()`。

另外 `platform.ts` 会给 `<body>` 加/去 `.is-mobile` class，并监听 `resize` / `orientationchange` 实时同步。

## 9. 注意事项与已知踩坑

### 9.1 构建相关（**高危，改前先读**）

| # | 坑 | 说明与对策 |
|---|---|---|
| 1 | **Electron 主进程只认 `.cjs`** | `package.json` 的 `main` 指向 `electron/dist/main.cjs`，但 `tsc` 只产出 `main.js`。**`build:electron` 脚本里的两步 `cp` 不能删**：<br>`cp electron/dist/main.js electron/dist/main.cjs && cp electron/dist/preload.js electron/dist/preload.cjs`<br>少了这步 → 打包进 exe 的是**旧 cjs**，会出现「小组件点复选框静默失败」等诡异现象 |
| 2 | **`compression` 不能设 `store`** | `electron/electron-builder.json` 的 `compression: "normal"` 是刻意的。`store` 对 `dir` 目标无影响，但 **portable 会继承，导致单文件 exe 从 69MB 膨胀到 272MB** |
| 3 | **`release-out/` 必须每次清理** | 这是 electron-builder 中间产物（~260MB）。不清理会被**增量复用**，把旧 `dist` 打进新包。`build.ps1` 的 `[0/3]` 步骤已自动清理（用 `node -e fs.rmSync` + `NODE_OPTIONS=''` 绕过沙箱安全删除拦截） |
| 4 | **构建前必须关闭正在运行的 exe** | `release/win-unpacked` 被运行中的 exe 锁定，builder 在 packaging 阶段会卡死。这也是 `electron-builder.json` 把 output 指向 `release-out` 的原因 |
| 5 | **`build.ps1` 必须是 UTF-8 带 BOM + CRLF** | PowerShell 读非 ASCII 源码必须要 BOM。`build.bat` 则是 3 行 ASCII（CRLF、无 BOM）的薄壳启动器 |
| 6 | **不要用 cmd.exe 做构建编排** | 历史教训：LF 行尾 + BOM + 嵌套 `call npm run` 会让 cmd tokenizer 崩溃报「此时不应有 ..」，导致 APK 已产出但没被打包。**整个编排层已换成 PowerShell，不要改回 .bat** |
| 7 | **Python 打印 emoji 会崩** | Windows 控制台默认 GBK，`print()` 含 🐮🐴 的文件名会 `UnicodeEncodeError`。**注意：文件其实写成功了，只是日志崩了**。`build.ps1` 已设 `PYTHONIOENCODING=utf-8` + `PYTHONUTF8=1`，`build_release.py` 里也加了 `sys.stdout.reconfigure(encoding='utf-8', errors='replace')` |
| 8 | **PowerShell 工具默认超时 120s** | 跑全量构建（electron-builder 约 2–3 分钟）必须显式传 `timeout: 600000`，否则日志停在 packaging 阶段，容易被误判为构建失败 |

### 9.2 部署相关

| # | 坑 | 说明与对策 |
|---|---|---|
| 9 | **CORS 是 JSON 数组不是逗号分隔** | `server/index.ts` 用 `JSON.parse(rawCors)`。格式错会直接抛错 |
| 10 | **移动端 origin 是 `http://localhost`** | 因为 `capacitor.config.ts` 设了 `androidScheme: 'http'`。CORS 白名单要加 **`http://localhost`**（不是 `capacitor://localhost`） |
| 11 | **后端部署后必须跑 `migrate.cjs`** | 子任务联动依赖 `tasks` 表的 `parent_id` 列。若客户端不联动，几乎都是 ECS 没跑迁移脚本 |
| 12 | **`deploy/server/.env` 含真实凭证** | 部署副本里有真实的 DB 密码和 JWT 密钥，**不要**上传到公开仓库或分享给外部 |
| 13 | **推 GitHub 必须 token 拼 URL** | `git push https://x-access-token:${TOKEN}@github.com/yan2468/Hpro_todo.git main`。直接 `git push origin main` 在无 tty 环境会报 `could not read Username`。**必须用 classic PAT（`ghp_` 开头，勾 `repo`），fine-grained PAT 一律 403** |

### 9.3 代码相关

| # | 坑 | 说明与对策 |
|---|---|---|
| 14 | **拖拽路径判定用 `isTouchMode()` 不是 `isMobileView()`** | 桌面窄窗口若走触摸路径会 `draggable=false`，彻底无法拖拽。详见 [7.3](#73-平台适配srcplatformts) |

### 10.2 ECS Nginx 配置的关键发现

排查过程中发现该 ECS 的 Nginx 有个**重要特点**：

> **`nginx.conf` 里没有 `include /etc/nginx/sites-enabled/*;` 指令！**
>
> 阿里云一键配置的 Nginx 模板把**所有 server block 都 inline 写在 `nginx.conf` 里**，`sites-enabled/` 下的软链形同虚设——修改 `sites-available/` 下的文件**不会生效**。

**排查这类问题的正确姿势**：

```bash
# 看 nginx 实际加载了哪些配置文件（最权威，比 ls sites-enabled/ 准得多）
sudo nginx -T 2>/dev/null | grep "configuration file" | sort -u

# 看 nginx.conf 的 include 指令
grep -n "include" /etc/nginx/nginx.conf
```

**新域名上线的正确做法**：在 `nginx.conf` 的 `http{}` 块末尾追加 `include /etc/nginx/sites-enabled/*;`，或把新 server block 直接 inline 写进 `nginx.conf`。
